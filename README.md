# SohuPro Observer Bot

Тестовый Telegram-бот для одного владельца услуги и одного read-only администратора. Бот работает через long polling, подключает **Автозаряд Pro** к одному TRON-адресу и сохраняет в PostgreSQL все значимые действия, ответы Sohu и движения тестового баланса.

## Что реализовано

- Единственный разрешённый клиент задаётся через `ALLOWED_USER_ID`, администратор — через `ADMIN_USER_ID`.
- Клиент при первом старте получает ровно `INITIAL_USER_BALANCE_TRX` (по умолчанию 100 TRX). Повторный рестарт баланс не начисляет.
- Администратор видит фактическое меню и состояние клиента, но сервер блокирует подключение, паузу, возобновление и отключение от его имени.
- TRON-адрес проверяется полностью: Base58, префикс `0x41` и checksum.
- Поддерживается только один адрес и тариф Pro (`high_frequency`, минимум 460 000 энергии за 72 часа, залог 15 TRX).
- Каждый запрос Sohu подписывается HMAC-SHA256 и целиком журналируется вместе с ответом, ошибкой и временем выполнения. Ключи и подпись в БД не сохраняются.
- Polling получает цену, операторский баланс, состояние адреса, все страницы операций и статистику адреса.
- Обработка операции идемпотентна по `used_tx_id`.
- Денежный ledger неизменяемый: каждая корректировка создаёт новую строку с остатком после операции.
- При выделении 131K списывается цена 131K + 0.3 TRX. Если реально потрачено не больше 65K, отдельной операцией возвращается текущая стоимость 65K. Комиссия не возвращается.
- При недостатке денег на максимальное следующее списание сервис автоматически отправляет Sohu `stop`.
- Когда технический кредит Sohu становится ниже стоимости двух выдач 131K, бот автоматически пополняет его без повторной передачи залога. Сумма ограничивается покрытием клиентского баланса.
- После timeout пополнения бот сначала сверяет фактический кредит Sohu и никогда не повторяет неопределённый запрос автоматически.
- После успешной попытки пополнения действует cooldown, поэтому задержанный ответ Sohu не приводит к повторным сообщениям каждую минуту.
- Пользователь и администратор получают одинаковые служебные уведомления о подключении, списании, возврате, паузе и отключении.
- При каждом запуске новой версии бот проверяет Telegram-токен и авторизованный `GET /user_info` в Sohu. Администратор получает подтверждение успешного деплоя либо сообщение с причиной ошибки связи.

## Денежные сущности

Они намеренно не смешиваются:

1. `app_users.balance_micros` — тестовый клиентский баланс.
2. `autocharging_subscriptions.souhu_credit_micros` — технический кредит адреса у Sohu.
3. `deposit_micros` / `deposit_status` — залог Pro.

Все TRX в БД хранятся как целое число микро-TRX (`1 TRX = 1 000 000`), поэтому расчёты не зависят от ошибок floating point.

## Запуск на VPS

Требуются Docker Engine и Docker Compose v2.

```bash
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f bot
```

Обязательные значения в `.env`:

- `BOT_TOKEN` — токен нового Telegram-бота;
- `ALLOWED_USER_ID` — Telegram ID клиента;
- `ADMIN_USER_ID` — Telegram ID администратора;
- `POSTGRES_PASSWORD` — используйте длинное значение из латинских букв и цифр; Docker Compose сам сформирует `DATABASE_URL`;
- `SOHU_API_KEY`, `SOHU_API_SECRET`.

Порт healthcheck привязан к `127.0.0.1` и наружу VPS не публикуется. Проверка:

```bash
curl http://127.0.0.1:3000/healthz
```

Остановка без удаления БД:

```bash
docker compose down
```

Не выполняйте `docker compose down -v`, если хотите сохранить журнал эксперимента.

## Локальная разработка

```bash
npm install
npm run build
npm test
npm run db:migrate
npm run dev
```

`npm run db:migrate` использует `DATABASE_URL`. Для локального запуска без Compose его нужно задать вручную. В Docker URL формируется из `POSTGRES_*`, а миграции применяются автоматически перед запуском бота.

## Где смотреть результаты эксперимента

- `provider_http_logs` — raw request/response каждого обращения к Sohu;
- `telegram_event_logs` — входящие Telegram updates и исходящие сообщения;
- `audit_events` — бизнес-события, snapshots аккаунта и статистики Sohu;
- `provider_usage_events` — неизменяемые нормализованные операции расхода;
- `provider_credit_topups` — все попытки автоматического пополнения кредита Sohu и результаты их сверки;
- `ledger_entries` — списания, возвраты, залог и остаток после движения;
- `autocharging_cycles` — 72-часовые циклы;
- `price_snapshots` — история полученных цен.

Примеры запросов:

```bash
docker compose exec db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "select created_at, method, path, response_status, response_body from provider_http_logs order by id desc limit 20"

docker compose exec db psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -c "select created_at, kind, amount_micros / 1000000.0 as trx, balance_after_micros / 1000000.0 as balance from ledger_entries order by id"
```

## Важные ограничения тестового MVP

- В публичном API нет отдельного метода полного удаления адреса: «Отключить» вызывает `status=stop` и сохраняет запись для аудита.
- При timeout подключения автоматический retry запрещён. Сначала нужно сверить `provider_http_logs` и состояние адреса у Sohu, иначе возможен повторный кредит/залог.
- Возврат залога не автоматизируется до фактической проверки полного 72-часового цикла.
- Событие без `used_tx_id` сохраняется в raw HTTP-журнале и audit, но не влияет на клиентский баланс.
- Если Sohu изменит форму ответа, неизвестный payload останется в журнале; неподтверждённое событие не будет списано.

## Проверки перед тестом

1. Убедиться, что операторский аккаунт Sohu имеет запас средств.
2. Проверить `SOHU_INITIAL_CREDIT_TRX` — это кредит адреса у Sohu, а не весь баланс клиента.
   `SOHU_CREDIT_RESERVE_ORDERS` задаёт нижний порог в количестве выдач 131K, а `SOHU_CREDIT_TOPUP_TRX` — максимальное разовое пополнение.
3. Нажать `/start` сначала клиентом, затем администратором.
4. Подключить отдельный тестовый TRON-адрес.
5. После каждой реальной USDT-транзакции сопоставить `provider_usage_events`, две возможные строки ledger (списание/возврат) и raw ответ Sohu.

> Telegram разрешает боту первым писать администратору только после того, как администратор хотя бы один раз открыл бота и нажал `/start`.
