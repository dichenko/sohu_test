# SohuPro Observer Bot

Telegram polling-бот для владельца `ALLOWED_USER_ID` и администратора `ADMIN_USER_ID` с доступом к просмотру. Владелец добавляет несколько TRON-адресов. У каждого адреса свои резерв, управление, статистика и полный Markdown-отчёт.

## Работа с адресами

Отправьте `/start` или `/menu`. Inline-меню показывает адреса с состоянием и остатком, по восемь на странице.

- **Добавить адрес**: введите TRON-адрес, затем начальный депозит в TRX. Base58Check проверяется до подключения.
- Депозит — виртуальный резерв адреса. Его задаёт пользователь без оплаты и общего лимита на аккаунт. Начальная сумма может быть нулевой; пополнение должно быть положительным. Поддерживаются точка/запятая и до шести десятичных знаков.
- **Пополнить депозит** добавляет введённую сумму к текущему резерву выбранного адреса. Другие адреса не затрагиваются.
- **Пауза / Включить / Отключить** управляют только выбранным адресом. Отключённый адрес сохраняется в списке и может быть включён снова.
- **Удалить из списка** требует подтверждения и остановки у Sohu. История остаётся в БД для аудита; адрес можно добавить заново. Операции до нового подключения повторно не списываются.
- **Последние 10** показывает десять последних операций и итоги выбранного адреса.
- **Полный MD** присылает файл с полной историей энергии, списаний, возвратов, комиссий и пополнений резерва. Время в отчёте — московское.
- `/cancel` отменяет текущий ввод.

Администратор видит адреса, меню, статистику и отчёты. Все изменения, в том числе поддельные callback-команды, блокируются. Бот работает только в личных чатах.

## Резерв и списания

Все суммы считаются в целых микро-TRX (`1 TRX = 1 000 000`); резервы хранятся в `numeric(38,0)`. Общий начальный баланс 100 TRX больше не начисляется.

При подключении Sohu получает `channel=high_frequency`, `hf_deposit=0`. Бот не удерживает реальные 15 TRX и не создаёт списаний залога. Если Sohu не разрешит Pro с нулевым залогом, бот сохранит ошибку и не подменит запрос платным залогом.

От виртуального резерва отдельно учитывается рабочий кредит адреса в Sohu. Начальный кредит и автоматические пополнения этого кредита по-прежнему расходуют средства операторского аккаунта Sohu. Пополнение виртуального депозита не является переводом в Sohu.

После окончательного подтверждения расхода (`un_delegate_success`) бот сохраняет отдельные движения списания и возврата. При выделении 131K списывается цена 131K + комиссия `SERVICE_FEE_TRX`; если использовано до 65K включительно — возвращается стоимость 65K. Комиссия не возвращается. Ключ идемпотентности включает адрес и `used_tx_id`.

Поздняя операция после паузы может сделать резерв отрицательным. Она будет отражена в отчёте, а адрес остановлен; история не зависает в бесконечных попытках списания.

## Предупреждения

Предупреждение об остатке отправляется пользователю и администратору для конкретного адреса, с кнопками пополнения и открытия карточки. По умолчанию порог — максимум из 10 TRX и стоимости трёх следующих выдач 131K с комиссией:

```dotenv
LOW_RESERVE_WARNING_TRX=10
LOW_RESERVE_WARNING_ORDERS=3
```

Одно предупреждение на период низкого остатка. После пополнения выше порога предупреждение вновь разрешается при следующем снижении. При нехватке на следующую выдачу останавливается только соответствующий адрес.

Уведомления о расходе, возврате, пополнении виртуального резерва и смене состояния доставляются через transactional outbox. Доставка пользователю и администратору учитывается раздельно: недоступный администратор не вызывает повторных сообщений пользователю. Технические polling-запросы и успешные пополнения рабочего кредита не создают регулярных Telegram-сообщений.

Подтверждение деплоя отправляется администратору один раз при старте процесса, после проверки Telegram и авторизованного `GET /user_info` Sohu. Администратор должен заранее открыть бота и отправить `/start`.

## Установка на VPS

Нужны Docker Engine и Docker Compose v2.

```bash
git clone https://github.com/dichenko/sohu_test.git
cd sohu_test
cp .env.example .env
nano .env
chmod 600 .env
docker compose up -d --build
docker compose logs -f bot
```

Заполните `BOT_TOKEN`, `ALLOWED_USER_ID`, `ADMIN_USER_ID`, `POSTGRES_PASSWORD`, `SOHU_API_KEY`, `SOHU_API_SECRET`. Пароль PostgreSQL используйте из латинских букв и цифр. `DATABASE_URL` Compose формирует автоматически.

Параметры кредита Sohu:

- `SOHU_INITIAL_CREDIT_TRX`: целевой начальный рабочий кредит адреса, не менее стоимости одной выдачи 131K;
- `SOHU_CREDIT_RESERVE_ORDERS`: целевой резерв Sohu в выдачах 131K, по умолчанию 2;
- `SOHU_CREDIT_TOPUP_TRX`: максимальное разовое пополнение рабочего кредита;
- `SOHU_CREDIT_TOPUP_COOLDOWN_SECONDS`: интервал между повторными пополнениями.

Фактический рабочий кредит ограничивается резервом конкретного адреса с запасом на комиссию. Успешный повторный запрос не содержит `hf_deposit`. Неопределённое пополнение блокирует дальнейшие пополнения и включение до сверки. После timeout сначала читается баланс Sohu; неясный результат не повторяется автоматически.

## Обновление со старой версии

Миграция `003_multiple_address_reserves.sql` скрывает прежние адреса из списка. Старые журналы, ledger и история сохраняются. Работающие старые подключения будут остановлены новым сервисом при первом цикле синхронизации. Их виртуальный остаток не переносится: новые суммы задаёт владелец при добавлении каждого адреса. Ранее удержанный залог Sohu миграция не возвращает и не списывает повторно.

Перед обновлением сохраните копию БД:

```bash
cd /opt/sohu_test
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > sohu-before-multi-address.sql
git pull --ff-only
docker compose up -d --build
docker compose logs --tail=100 -f bot
```

Миграции применяются автоматически перед запуском. Старые переменные `INITIAL_USER_BALANCE_TRX` и `PRO_DEPOSIT_TRX` игнорируются и могут быть удалены из `.env`.

Healthcheck: `curl http://127.0.0.1:3000/healthz`. Внешние входящие порты для polling не требуются. База сохраняется в Docker volume. `docker compose down -v` удаляет её.

## Журналы и разработка

- `autocharging_subscriptions`: адреса, состояния, независимые остатки и предупреждения;
- `ledger_entries`: виртуальные пополнения и все движения по адресу;
- `provider_usage_events`: окончательные операции энергии;
- `provider_credit_topups`: попытки пополнения рабочего кредита;
- `notification_outbox`: очередь уведомлений и доставка по получателям;
- `provider_http_logs`: запросы и ответы Sohu, статусы, ошибки и длительность без ключей;
- `telegram_event_logs`, `audit_events`: действия и исходящие сообщения;
- `price_snapshots`: история цен Pro;
- `autocharging_cycles`: исторические записи предыдущей версии.

```bash
npm ci
npm run build
npm test
```

Проверки БД используют локальный PostgreSQL WASM в памяти, а Sohu/Telegram заменяются тестовыми ответами. Рабочие API и сервер тестами не затрагиваются. Для разработки вне Docker задайте `DATABASE_URL` и выполните `npm run db:migrate`.
